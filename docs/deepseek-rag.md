# 从文件到带引用回答：使用 DeepSeek 的两种方式

检索前要判断「这是什么问题」，检索后要判断「这些资料够不够」，生成后要核对「这句话是否有出处」。这三件事分开执行：意图模型只负责第一件，它的判断不是证据。默认不开云模型，仍可在本地用 BM25 检索并预览证据。

## 1. 填写本机配置

编辑仓库根目录的 **`.env`**（Git 忽略），找到 `DEEPSEEK_API_KEY=`，只在等号右侧填写真实 Key。`.env.example` 是空白模板，不要把真实 Key 写入或发给前端。百炼的 `RAG_CLOUD_API_KEY`、MinerU 的 `MINERU_API_KEY` 是独立凭据，不会被拿来访问 DeepSeek。

| 想得到的行为 | `.env` 中要开启的开关 | 哪些内容会发送给 DeepSeek |
| --- | --- | --- |
| 只用 DeepSeek 替代 Laya 做意图判断，保留现有检索与回答配置 | `RAG_ENABLE_DEEPSEEK_INTENT=true`，保持 `RAG_ENABLE_DEEPSEEK_ANSWERS=false` | 至多一次分类请求：当前问题和“是否有历史 / 是否有 SKU”两个布尔值。不附带文档、历史正文或单独的 SKU 字段；写在问题中的信息自然会随问题发送。 |
| 在上述基础上，用同一个 Key 得到有出处的自然语言答案 | 再加 `RAG_ENABLE_DEEPSEEK_ANSWERS=true` | 对当前账号可见的证据片段、问题、缺项、待核验的结论；若启用云查询预处理，相关阶段还会使用历史等查询上下文。只有在允许资料发往此提供商时才开启。 |

两个开关独立；只填 Key 而不开开关不会启用 DeepSeek。启用开关而缺 Key 会在启动时报配置错误。默认分类与问答模型均为 `deepseek-flash`；可分别设置 `RAG_DEEPSEEK_INTENT_MODEL`、`RAG_DEEPSEEK_ANSWER_MODEL`。应用只请求 DeepSeek 官方 Chat Completions，使用 JSON 输出并关闭思考模式；不启用联网搜索或外部工具。协议参考：[模型列表](https://api-docs.deepseek.com/quick_start/pricing/)、[JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

在仓库根目录启动（修改 `.env` 后需重启本地进程）：

```powershell
uv run adaptive-rag --env-file .env serve
```

CLI 不会自动读取 `.env`；同名进程环境变量优先。初次使用新数据目录还需配置本机的 `RAG_ADMIN_PASSWORD`。从 `http://127.0.0.1:8000/` 登录，查看工作台能力或已认证的 `GET /capabilities`：`plugins.decision.plugin=deepseek` 表示已选择意图模型；`generation_enabled` 和 `semantic_support_verification` 分别表示已配置生成及语义核验。能力页不主动测试密钥是否有效。

## 2. 从入库到回答

1. **上传并发布。** 在「知识文件管理」上传资料，设置分类和版本；管理员核对后发布。暂存不等于已能检索。PDF / Office 在文件中心使用 MinerU 时需另行同意上传完整原件；参见[文件管理](file-center.md)。
2. **提问与分流。** 例如资料中有「HX-220 500ml 保温杯」，可问「HX-220 可以放洗碗机吗？保修多久？」。模型可以建议普通知识检索、按明确型号检索、澄清、问候、实时业务或人工路径。明显的问候、实时请求和缺少商品指代等先由本地规则处理。用户主动问「我的包裹现在到哪了」不会查询物流；请求人工也不会创建工单。知识问题如「物流状态有哪些」仍可以查手册。
3. **只搜授权资料。** 查询固定在一个快照，按当前身份、资料分类和可信 SKU 确定候选范围，再做精确标识符匹配或常规检索。意图模型不能选择租户、指定资料、推断可信 SKU 或放宽权限。若文件本身限定了商品范围，仍须提供可信的 SKU 字段，不能用模型猜测的商品代替。原始检索通道、融合、来源检查不因意图模型的一句话被关闭。按型号查不到不会改搜相似型号来凑答案。单独上传的图片仍由图片资料库检索，不等于这里进行了看图推理。
4. **决定是否要补查。** 问题分解、改写、多查询、HyDE 只在相应插件已配置且本轮允许时执行。个人关闭的可选步骤不会被模型重新打开。开启意图路由时，用问号或分号明确列出的子问题会分别保留，避免云规划器漏掉一问。默认最多 3 个子问题、12 条检索通道；检索后及生成后的定向补查共享最多一次机会。HyDE 生成的假设文本仅用于召回，不能成为回答的出处。
5. **看结果与来源。** 没有相关内容时返回 `empty`；有资料但不足时用 `insufficient` 说明，不强行作答。若保温杯手册只写了保修，没有说明能否进洗碗机，开启质量检查后应给有依据的部分并说明缺项，或在证据不足时拒答。不会用模型常识补一个洗碗机结论。没有生成器时只显示 `evidence_preview`。开启 DeepSeek 问答时，生成后再核对事实支持性与完整性，只有被接受的结论才返回；审查器并不保证不会误判。点击「来源」查看相应原文；打开历史对话时重新校验当前访问权限。

## 3. 扩展、成本与故障排查

- **只用一个 DeepSeek Key：** 可用本地 BM25 + DeepSeek 生成、核验。它不会启用 Embedding、Reranker 或图片语义索引。已有百炼时保留 `RAG_ENABLE_CLOUD=true` 和百炼凭据，可以继续用其 Embedding / Reranker；如果也开启 DeepSeek 问答，聊天类插件使用 DeepSeek，而不是重复向两家生成答案。
- **按需开增强：** `RAG_ENABLE_QUERY_PREPARATION=true` 提供语义分解和上下文改写；`RAG_ENABLE_MULTI_QUERY=true` 和 `RAG_ENABLE_HYDE=true` 分别允许额外查询。DeepSeek 问答自带充分性检查、定向补查和生成后语义核验，不依赖百炼质量开关。一次问答可能累计多次计费调用，不是一次意图请求就能完成整个问答。
- **分类失败不是检索失败：** 分类超时、限流、鉴权失败或返回不符合约定的 JSON 时，不重试收费请求；改走本地规则，以原问题检索，不开启额外查询变换。该回退只针对意图判断。后续生成或语义核验失败会显示错误，不把未核验的草稿交给用户。取消查询或访问权失效不会被当成可重试的模型错误。
- **验证效果：** 用一份公开测试手册，分别问一个有出处的事实、一个库外问题、一个易混淆型号和一个实时订单问题。查看「前置决策」的路由、建议步骤与回退原因，对照实际执行、模型调用记录、来源和结果，而不仅看服务有没有启动。规则和模型都不是完整的语义判别器；本地模拟测试能验证流程，真实分类、召回与回答质量需业务问题集验证。
