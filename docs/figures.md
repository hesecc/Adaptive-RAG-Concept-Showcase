# 文档里的插图

用 MinerU 解析 PDF 时，文中的插图随文档入库。问题命中带插图的段落时，图片、题注和页码跟着来源一起返回，页面在回答和证据卡里显示图片，生成模型读到「这里有一张什么图」。系统不看图本身，下面的链路、权限和限制都建立在这一点上。

## 链路

1. **解析。** 只有 MinerU 后端提取插图（`RAG_PDF_BACKEND=mineru`）。本地后端只读 PDF 文字层，不提取图片。MinerU 结果包里，`full.md` 用 `images/<哈希>.jpg` 引用图片，`*_content_list.json` 记录每张图的题注和页码（0 起的 `page_idx`，入库时加 1）。只读被 `full.md` 引用的 `image` 和 `chart` 两类。表格截图不取，因为表格已经以 HTML 文字在正文里。题注依次取 `<类型>_caption`、`<类型>_footnote`、`content`：MinerU 把图表的题注放在脚注字段里，所以不能只看 `caption`。
2. **校验与改写。** 图片须是静态的 PNG、JPEG 或 WEBP，不超过 10 MB、2,500 万像素、单边 16,384 像素（与图片资料库同一套检查）。通过的写入内容寻址对象库，键是图片字节的 SHA-256，正文里的引用改写成一行：

   ```
   ![Figure 1: Transformer 模型架构。](ragfig:<64 位 sha256> "第 3 页")
   ```

   没通过、缺失或超限的图连同这一行一起去掉，周围的正文保留。题注超过 160 字时截断，方括号换成圆括号，控制字符换成空格，所以题注无法提前结束这一行。正文里恰好写成 `![…](images/…)` 的文字（例如讲解 Markdown 语法的示例）会被同样处理，找不到对应图片就被去掉。
3. **分块。** 插图行与表格、公式一样作为整体保留在所在段落里。一行最长约 250 字，默认子块 320 字容得下；配置里的 `child_chars` 调到 250 以下时，这一行可能被切开，图和题注会分离。
4. **检索。** 题注是普通的块文本，参与 BM25、向量和重排。BM25 把 `ragfig:<sha256>` 当作一个词，不影响其他词的统计。相似度判定先把插图行还原成题注再比对，所以存储键不会让一段文字被当作命中。送给向量模型、重排模型和生成模型的文本里，插图行写成 `［插图：题注，第 3 页］`，不含存储键。
5. **证据。** 命中的证据带 `images`，每张图一项：`{"key", "caption", "page"}`，取自证据正文。证据按字符预算截断时，不会切在插图行中间。
6. **展示。** 回答下方的「相关插图」列出回答依据的证据里的图：有引用结论时只列被引用的证据，没有引用结论的证据预览列出全部。`insufficient`（只找到最接近的资料）不进「相关插图」，图只出现在各自的证据卡里。证据卡和来源弹窗也显示图片，图下标注题注、文档、页码和证据编号，点击在新标签页打开原图。图片加载失败时显示「这张图片暂时无法显示。」

`ingest --file <PDF>` 的返回里多一项 `figures`：`{"referenced": 引用数, "stored": 已保存, "skipped": 被去掉}`。本地后端三项都是 0。

## 权限

插图没有自己的 ACL，它跟着出现它的证据。

`GET /evidence/{generation}/{evidence_id}/images/{key}` 要求：

- 已登录；
- 当前账号能读这条证据，检查与证据回源相同（同租户、文档未删除、数据分类允许）；
- `key` 出现在这条证据的正文里；
- PDF 解析入库时已为当前租户、文档、版本、不可变修订 ID 和该图片键写入绑定记录。读取时先核对这条记录，再取图片字节。手写标记、旧正文和单独的对象键都不能代替绑定记录。

只有本次解析实际引用且通过图片校验的键才计入修订元数据。每个键另有一条内容寻址的二进制绑定记录；不从正文反推或补齐记录。写入中断后可以重新导入同一份 PDF，缺失的记录写入前，相应图片不可读。

键格式不对返回 400；标记或绑定缺失、证据不可读、快照不存在都返回 404。撤权后，同一个地址也返回 404。响应头带 `Content-Disposition: inline` 和 `Cache-Control: no-store`。只允许 GET。

## 限制

这些上限写在代码里，没有对应的环境变量：

| 项 | 上限 | 超出时 |
| --- | --- | --- |
| 每份 PDF 的插图数 | 200 | 后面的图被去掉 |
| 单张图片 | 10 MB | 这张被去掉 |
| 一份结果包里的图片合计 | 60 MB | 超出部分被去掉 |
| `*_content_list.json` | 8 MB | 不读，图片仍入库，没有题注和页码 |

## 它能做到什么，做不到什么

- **验证过的。** 用真实的 MinerU 结果包（一篇中文版 Transformer 论文，`full.md` 引用 4 张图）在无模型模式下离线跑通：4 张全部入库，题注和页码取自 `content_list`（Figure 3、5 的题注来自脚注字段）；问「Transformer 模型架构图」时，Figure 1 所在的段落排第一并带图，图可以取回；问库里没有的话题得到 `empty`。管理员账号在本机浏览器里看过回答下方的「相关插图」、证据卡、来源弹窗、图片缺失时的提示和手机宽度（390 px）的排版；普通账号读不到财务分类文档的插图（404）是用 HTTP 请求核对的。其余是单元测试和 HTTP 测试，覆盖损坏的结果包、恶意题注、超限、越权和撤权。
- **没有视觉模型。** 图只能通过题注和周围的文字被找到。没有题注的图，要靠所在段落的文字带出来；图里的文字（坐标轴、标签）不参与检索。生成模型也看不到图，只知道题注和页码。
- **云端路径只用模拟传输验证过。** 向量、重排和生成收到的是 `［插图：…］` 而不是存储键，这一点有测试；没有用真实模型验证过生成答案会怎样提到图。
- **网页 PDF 与 CLI 的区别。** 文件中心可上传自带文字层的 PDF（最多 10 MB），网页只用本地解析器，不提取插图。要保留 MinerU 的插图、题注和页码，使用 CLI 的 MinerU 后端。
- **表格截图不提取。** 表格以 HTML 文字入库，可检索，页面里显示为文字。
- **页码不是坐标。** 页码来自 MinerU；文字证据仍按解析后的 Markdown 定位，没有页内坐标，不能在原页面上高亮图的位置。
- **旧修订不迁移。** 已有正文、快照和归档对象保留可读；旧标记仍可能出现在证据列表中，但取图返回 404。需要插图时，重新解析源 PDF 并发布新修订。即使文档版本号和正文未变，新绑定也不会授权旧修订。
- **对象不回收。** 删除文档不会删除对象库里的插图（原 PDF 的归档也是如此），没有保留期限，也没有垃圾回收。
- **这条图片路径需要 nginx 配置。** 部署模板把它放进 `an_rag_media` 限速区（每分钟 300 次，突发 120）。宿主 nginx 重载前，它落在严格的默认区（每分钟 30 次，突发 10），一页几张图就可能被限速。
