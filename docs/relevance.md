# 没找到相同或相似内容时怎么办

检索总会排出名次：BM25 只要有一个字相同就给分，向量检索没有下限。如果不加判断，问一个库里根本没有的问题，也会拿到「最接近」的几段当作来源。本文说明系统怎样判断「库里没有相同或相似的内容」，以及这个判断能做到什么程度。

## 规则

每个子问题的候选在重排之后、选取证据之前，先过一次相似度判定（trace 里的阶段 `relevance.<子问题ID>`）。候选满足下面任一条就保留，否则丢弃：

1. **重排分数**：候选带有重排分数（云端模式），且不低于 `RAG_RELEVANCE_RERANK_FLOOR`（默认 0.05）。
2. **词面重合**：候选包含问题主题词的比例不低于 `RAG_RELEVANCE_LEXICAL_FLOOR`（默认 0.3），或至少包含 3 个主题词。
3. **没有判断依据**：开了向量检索却没有任何重排分数，或问题里提不出主题词。这时不丢弃任何候选，由后续的证据充分性检查把关。

主题词的取法：先去掉疑问和客套用语（什么、怎么、请问、多少……），剩下的中文取相邻两字，含「的、了、是」这类虚字的字对不算，英文和数字标识符（如 `gpt-4`）整体保留，单字不算。问题被改写、扩展或补检索时，候选只要接近其中任一种说法就保留。

判定结果体现在回答状态里，页面和接口都能区分：

| 状态 | 含义 | 来源 |
| --- | --- | --- |
| `empty` | 在当前账号有权访问的知识库中，没有找到与问题相同或相似的内容 | 不返回任何来源 |
| `insufficient` | 相关资料不足以回答，或生成的陈述未通过支持性核验 | 当前回答和选中的历史轮次直接列出本轮授权片段，可点「查看原文」复核；这些片段不是已核验的答案 |
| `evidence_preview`、`partial`、`answered` | 找到了相似内容 | 返回来源 |

无模型模式只按词面判断，`empty` 的提示会注明这一点。多个子问题时，没有相似内容的子问题会出现在 `missing_query_ids` 里，其余子问题的来源照常返回。

每次判定的数字（主题词、候选数、保留数、最高词面比例、最高重排分数、前 20 个候选的明细）都写在 trace 的 `relevance.*` 阶段里，用来解释为什么某段内容没有被当作来源。

## 配置

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `RAG_RELEVANCE_GATE` | `true` | `false` 关闭判定，恢复「总是返回最接近的几段」 |
| `RAG_RELEVANCE_LEXICAL_FLOOR` | `0.3` | 0 到 1。越高越容易判为「没有」 |
| `RAG_RELEVANCE_RERANK_FLOOR` | `0.05` | 0 到 1。只对带重排分数的候选生效 |

同名字段也可写在 TOML 配置里（`relevance_gate`、`relevance_lexical_floor`、`relevance_rerank_floor`）。

## 它能做到什么，做不到什么

词面阈值用本地合成样本校准：10 份中文业务文档（退换货、运费、会员、发票、保修、支付、优惠券、隐私、客服、门店）、一篇经 MinerU 解析的 Transformer 论文，以及本项目的 4 份说明文档，共 241 个块。样本里有 64 个应当找到的问题（52 个短问题、12 个长问题）和 36 个库里没有的问题（30 个短、6 个长）。统计口径是：每个问题取词面占比最高的块（应当找到的问题只在预期文档内找），不经过 BM25 候选截断，所以只反映规则本身，不是端到端结果。

| 问题类型 | 结果 |
| --- | --- |
| 应当找到的短问题 | 保留 47 / 52 |
| 应当找到的长问题 | 保留 12 / 12 |
| 库里没有的短问题 | 判为没有 21 / 30 |
| 库里没有的长问题 | 判为没有 6 / 6 |

- **会漏掉改写。** 丢掉的 5 个短问题中，3 个与原文没有任何共同的词：「满多少钱包邮」（原文是「订单满九十九元免基础运费」）、「买了东西想退怎么操作」、「快递要多久」。另外 2 个只有一小部分词重合，占比 0.25，低于 0.3：「优惠券能和会员折扣一起用吗」和「为什么要对点积除以根号 dk」。云端模式下，重排分数不低于 0.05 的候选也会保留，改写类问题因此有机会被找回，但这一点没有用真实模型验证。
- **会放过同领域的外行问题。** 放进来的 9 个短问题多是论文的同领域邻居，或只撞上常见词。例如「怎么用 PyTorch 训练模型」命中论文里的「训练模型」，「GPT-4 的参数量是多少」命中「参数」和「数量」。无模型模式分不出这种差别；云端模式下只能靠充分性检查给出 `insufficient`。
- **样本是自己写的。** 规模小，问题以中文为主，库里没有的问题里有刻意选的同领域问题。它说明规则在这批数据上的取舍，不是线上准确率。校准脚本和语料留在本地，没有放进仓库。
- **重排阈值 0.05 是默认启发值，不是经过业务语料校准的概率阈值。** 重排分数不能直接解释为答案正确概率，接入真实语料后应结合查全和误召回结果重新选择阈值。协议细节见[百炼接口笔记](research/bailian-api-notes.md)。
- **云端的补检索没有改。** 质量检查开启时，库里没有的话题仍会触发一次补检索，其中包含一次查询生成调用。
- **评测指标包含判定的影响。** 判定在检索之后、计算指标之前生效，被丢掉的块不计入召回；无标注问题的「未找到率」统计的就是这类答复。调阈值时用 `RAG_RELEVANCE_GATE=false` 再跑一次作对照。图片资料库的检索有自己的空结果规则，不经过这个判定。

要在自己的资料上校准，把应当找到和库里没有的问题写进评测集（见[评测](evaluation.md)），对比不同阈值下 `empty` 的比例，再调整环境变量。
