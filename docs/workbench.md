# 检索工作台

工作台由 FastAPI 同源提供，静态文件随 Python 包发布。页面将历史对话、回答和检索诊断分区展示；检索状态、阶段耗时与证据来自后端。

## 登录与运行

1. 启动应用，在浏览器打开服务根路径 `/`。本地默认地址是 `http://127.0.0.1:8000/`；云部署使用该实例 HTTPS 入口。使用私有 CA 时，应先信任并核对实例的公开 CA。
2. 输入管理员分配的账号和密码登录。固定管理员为 `ragadmin`，口令由部署者在环境变量 `RAG_ADMIN_PASSWORD` 中设置；无需填写 HTTP Key、云模型 Key 或 MinerU Key，云平台凭据继续由服务器管理。
3. 在中间输入问题并发送。左侧「历史对话」按账号显示；点开标题可以继续提问，或用「新对话」开启另一个话题。
4. 在左侧执行链路选择步骤，查看右侧的状态、耗时、开始偏移和结构化返回。中央对话区展示问题与回答，右侧还可查看证据、模型调用和 JSON。
5. 回答按结论分段，段末的「来源 1」「来源 2」对应本轮证据列表中的序号。点击编号即可按当前权限读取那段原文。历史对话中点击「查看本轮流程」也可展开该轮的引用；不需要重新提问。证据视图保留「查看原文」，截断标记表示摘录不是完整文档。

打开历史对话不会重新检索或调用模型。执行详情与证据来自保存的 Trace，ID 仅用于诊断，可在 JSON 查看。旧记录缺少最终回答时不补造答案。

首个查询前应已通过文件管理页或现有 CLI / HTTP 接口导入并发布知识。没有已发布快照时，工作台显示 `no_index`；无模型配置时，仍可执行 BM25 等基座能力，返回证据预览。可选的 [DeepSeek 意图路由](deepseek-rag.md) 会在「前置决策」里显示路径、建议步骤以及是否因外部服务不可用而退回规则。问实时库存或请求人工时，工作台会说明能力边界，不会伪装成已执行的操作。

## 回答与证据图表

回答先给核心结论，再按问题组织原理、对比或步骤。页面支持小标题、列表、重点、代码块和简单的 Markdown 表格。连续使用同一组证据的结论共用一组「来源 N」，新小标题另起一段。点来源可查看本轮授权原文；选中历史轮次也能回源。顶部「检索证据」统计返回的授权证据，「正文引用」统计正文实际使用的不同证据。

部分回答会另列缺少证据的子问题，证据不足时可显示仅供参考的授权片段，未找到相关内容时则给出明确提示。

当引用的证据摘录包含可识别的 Markdown 或简单 HTML 表格时，工作台可在回答下方展示 **证据图表**。例如，月份与出货量对应趋势图，地区与净增长对应带零基线的柱状图，明确编号的操作步骤对应流程图。展开「查看原始数据」可核对原表的行序、数值与单位，点击「来源 N」可回看原文。

- 需要至少 3 行数据。日期必须可识别，趋势图按实际时间间隔绘制；分类对比最多 12 类；流程必须有从 1 开始的连续步骤号。多个数值指标分别绘图，不混用坐标轴。每轮最多展示两张图。
- 不从生成文本中的数字猜趋势，也不合并不同来源。摘录被截断、证据不足、单位混杂或表格结构不支持时，不作图；仍可查阅有权限的证据。无模型的「证据预览」也能展示原表图，但不代表已生成答案。

## 个人检索设置

打开左侧「检索设置」，可选择证据数量、限定商品 SKU，以及决定是否使用服务端已开启的查询改写、多路扩展或 HyDE（用假设答案辅助检索）。改动从下一次提问生效，不改变历史结果。点「恢复默认」可清空 SKU，将证据数恢复为 5 并沿用服务端默认步骤。

偏好按**租户和账号**保存在本浏览器，不跨设备同步，也不改变其他人的查询或服务端配置。被服务端禁用的步骤置灰；权限检查、基础检索、证据核验、资源上限不能在这里关闭或绕过。执行详情会说明某一步是否因个人选择而跳过。

## 账号管理

以 `ragadmin` 登录后，打开顶栏「账号管理」，输入用户名和密码即可创建普通账号，并把这组凭据分配给使用者。账号列表显示用户名、身份和创建时间；删除普通账号后，其已有登录会话立即失效。固定管理员始终保留，不能通过此界面删除；没有自行注册入口。

用户名为 3–32 位字母、数字、下划线或连字符，保存时去除首尾空格并统一为小写；密码为 6–128 位，不接受控制字符。重复账号会明确报错。普通账号不会看到账号管理入口，也不能通过相应 HTTP 接口管理账号。

账号和会话保存在数据目录下的 `accounts.sqlite3`，服务重启后保留。登录会话有效期为 7 天；浏览器刷新会恢复未过期会话，退出登录会使当前会话失效。删除后重新创建同名账号会产生新的内部身份，不会沿用旧账号的独立文档授权。当前工作台共享所配置的知识库租户，文档的既有访问规则仍然有效。

部署时可用 `Settings.browser_tenant` 或 `RAG_HTTP_TENANT` 指定浏览器知识库租户；未显式指定时沿用唯一管理员 token 所在租户，否则使用 `demo`。已有账号数据库与配置租户不一致时拒绝启动，应核对原配置后再启动。

## 数据视图

| 视图 | 显示的数据 |
| --- | --- |
| 执行链路 | 实际阶段顺序、运行/完成/失败状态、服务端耗时、明确的禁用与跳过原因 |
| 步骤详情 | 该步骤记录的结构化返回，例如问题规划、查询变体、召回命中、排序、证据覆盖与核验结果 |
| 回答 | 最终状态、已返回回答、逐条结论与引用，以及尚未覆盖的子问题 |
| 证据 | 文档版本、标题路径、出处、摘录和引用元数据，可再次回源；证据带插图时同时显示图片，见[文档里的插图](figures.md) |
| 模型调用 | 实际请求尝试、模型、接口、耗时、状态与平台返回的 Token 用量 |
| JSON | 本次最终结果与授权 Trace，可下载用于诊断 |

阶段输出是显式业务结果，不包含模型内部推理过程。模型配置关闭时调用数为零；平台未返回的用量不补造。运行中的页面等待耗时来自浏览器计时，结束后切换为服务端 Trace 耗时；两者测量范围不同。服务端阶段耗时与总耗时也包含各自测量范围，不应假定所有阶段之和等于端到端网络时间。

## HTTP 事件契约

`POST /query/stream` 接受与 `POST /query` 相同的严格 JSON 输入，普通登录账号和管理员均可使用。浏览器使用同源 `fetch`，携带 `an_rag_session` Cookie 读取 SSE；现有维护客户端也可继续通过 `Authorization: Bearer ...` 鉴权。

```json
{
  "question": "Transformer 的注意力机制如何工作？",
  "top_k": 5,
  "skip_query_steps": ["hyde"],
  "persist_conversation": true
}
```

`skip_query_steps` 可省略，只接受 `rewrite`、`multi_query`、`hyde`。它只表示本次请求跳过哪些可选步骤，不能启用插件或写入其他用户的偏好。

| 事件 | 数据 | 发生时间 |
| --- | --- | --- |
| `trace` | `trace_id`；持久对话另含 `conversation_id` | 本次执行开始 |
| `stage` | 阶段索引、名称、状态、开始偏移与已完成耗时等元数据 | 对应阶段实际开始或结束 |
| `result` | `result` 与 `trace` | 查询完成、Trace 持久化且当前权限检查通过后 |
| `error` | 安全的错误代码、说明、`error` 诊断对象、可用的 `trace_id`；权限复核通过且记录可读时附带 `trace` | 流式响应开始后的执行失败 |

身份和输入校验失败可在建立事件流之前返回常规 HTTP 错误。事件流建立后，HTTP 200 只表示连接已建立；调用方必须等到 `result`，或处理 `error` 与提前断开。前端不会因连接错误自动重复提交付费查询。

失败事件中的 `trace` 通过与历史回放相同的当前权限检查。旧服务未附带 Trace 或流连接提前断开时，页面至多尝试一次只读 `GET /traces/{id}` 恢复记录。模型调用记录可包含固定白名单中的 `error_code` 与网络/超时异常类别 `error_type`，不保存上游异常正文、请求头或密钥。网络与超时错误不自动重试；旧记录未保存具体异常类别时，页面只说明可证实的失败原因。

主动取消的记录使用独立的 `query_cancelled` 诊断，历史回放也显示取消原因。若查询已完成、仅终态记录读取临时失败，恢复的 Trace 含 `final_result` 时按已保存的最终结果显示回答与证据。

`GET /console/session` 返回当前登录账号、管理员标记、可信身份及插件配置，页面刷新时通过它恢复登录。`GET /traces/{id}` 读取同租户历史 Trace，并按当前访问权限检查其中的源内容。旧 Trace 未记录的步骤输出或最终回答明确显示缺失，不伪造回放数据。

## 会话与权限

首次提问不传 `conversation_id`；续聊时传首轮返回的 ID。列表用 `GET /conversations?limit=20&offset=0`，按 `has_more` 和 `next_offset` 翻页（撤权后可能不足一页）。`GET /conversations/{id}` 按时间返回问答摘要；详情按所选轮次单独读取。打开列表、回看和新建空白话题都不会调用模型。

- 页面和静态资源可公开加载，业务数据要求有效登录会话或兼容的 Bearer 身份。普通账号可使用检索、执行链路和证据视图；账号管理、文档维护和作业读取仍要求管理员。
- 登录会话通过独立的 `an_rag_session` Cookie 保持，刷新页面自动恢复未过期会话。密码不写入浏览器存储或下载文件；退出、登录失效或切换身份时清除页面中的旧查询与结果。
- 会话按租户和稳定账号 ID 隔离，管理员的历史列表也只显示本人。「新对话」不删除历史。升级时有可信身份且可复核来源的旧记录按单次提问列出；不能验证手填历史来源的旧记录不进入列表。
- 续聊由服务端选取最近三轮有答案的 answered / partial 问答作为上下文，不接受客户端拼接的历史。重新打开和续聊都按当前权限检查整段记录及其依赖；任一轮来源失效时不返回整段，可另开对话。撤权不能远程收回用户已经收到或下载的内容。
- 单段对话最多 64 轮。达到上限后仍可回看，下一次提问请新建对话。新请求仅在指定 `persist_conversation: true` 或续聊时进入侧栏；未加入侧栏不等于不保存诊断 Trace。
- 工作台将请求绑定到当前租户和账号。另一标签页换号后，旧身份发出的请求会被拒绝，不会把提问记入新账号。业务接口仍以 Cookie 或 Bearer 认证为准，身份标头不能用于授予权限。
- 续聊在每次内置云模型发送（含重试）前复核当前身份和历史来源；返回详情和结果之前再检查一次。撤权可阻止后续调用，但不能撤回当时已合法发送给模型的请求。
- 文档、问题、生成文本及结构化数据均以文本节点呈现，不执行其中的 HTML 或脚本。
- 「停止本次查询」中止浏览器请求并取消服务端协作式查询。同步线程或不协作的插件仍受现有超时限制，不能将取消描述成进程级强制终止。

## 部署

静态文件位于 `adaptive_rag/static/`，由 setuptools package-data 纳入发行包。现有 Dockerfile 复制整个 `adaptive_rag` 包，因此无需 Node 运行时、额外容器或新增中间件。发布工具的运行文件白名单必须包含这四类静态资源：HTML、CSS、JavaScript、SVG。

HTTPS 代理需要允许 `/`、`/static/*`、`/auth/*`、`/admin/users*`、`/console/session` 与 `/query/stream` 访问同一个应用，保留 `Cookie`、`Set-Cookie` 和兼容客户端的 `Authorization`，并关闭 SSE 代理缓冲。不要过滤登录 Cookie，也不要覆盖同机其他项目的 Cookie。发布后需验收严格 TLS、账号登录与退出、静态资源加载、实时阶段事件、最终结果和回源权限。页面内容安全策略与响应头由应用提供，不能以代理上线代替浏览器验收。
